Présentation de l'audit

Cet audit a été conduit sur l'ensemble de la stack Fleet Management System : backend Laravel 11 (API REST + Sanctum), frontend React (Vite + React Router), et infrastructure Docker. L'analyse couvre les 14 vulnérabilités identifiées selon le référentiel OWASP Top 10 : 2021, classées par sévérité.

Les deux vulnérabilités critiques permettent une compromission totale du système (élévation de privilèges admin sans authentification préalable). Elles doivent être corrigées avant tout déploiement en production.

✓ Points positifs relevés

✓Blocage progressif (exponential backoff) — Max 5 tentatives, puis blocages de 5 min → 30 min → 2 h → 24 h, conforme NIST SP 800-63B.
✓Politique de mot de passe forte — Min 8 caractères, majuscule, chiffre, symbole, vérification HaveIBeenPwned (uncompromised()).
✓Rate limiting sur les routes publiques — throttle:10,1 sur /register et /login, throttle:5,1 sur reset-password.
✓Soft delete — Les utilisateurs ne sont pas supprimés physiquement, préservant l'audit trail.
✓Gates RBAC cohérentes — Séparation admin/manager/accountant/driver/mechanic correctement définie dans AuthServiceProvider.
✓Message d'erreur générique — La route de login ne distingue pas "email inconnu" de "mauvais mot de passe" (conforme OWASP).
✓Gitignore protège .env — Le fichier .env est exclu du dépôt Git. Fichier database.sqlite également exclu.
✓Notification par email lors d'un blocage — L'utilisateur légitime est alerté par AccountLockedNotification.

🔴 Vulnérabilités Critiques

C1 — Broken Access Control

Auto-élévation de privilèges à l'inscription publique

OWASP A01:2021 – Broken Access Control
🔴 Critique

N'importe quel visiteur non authentifié peut créer un compte avec le rôle admin directement depuis le formulaire d'inscription public. Le frontend envoie explicitement le rôle sélectionné et le backend l'accepte sans restriction.

📄 fleet-mgt-frontend/src/pages/Register.jsx:47 📄 fleet-mgt-api/app/Http/Controllers/AuthController.php:28 
// Register.jsx — le rôle est envoyé librement par le client
api.post('/register', { name, email, password, role: form.role });

// AuthController.php — 'admin' est accepté comme valeur valide
'role' => ['sometimes', 'in:admin,manager,driver,accountant'],

Impact : Compromission totale — un attaquant crée un compte admin, accède à toutes les données du parc, peut supprimer des utilisateurs et des véhicules.

✓ Correction

Retirer admin des rôles acceptables sur la route publique. Toujours forcer driver par défaut à l'inscription :

// AuthController.php — correction
'role' => ['sometimes', 'in:manager,driver,accountant'],
// ou forcer directement :
$user->role = 'driver'; // ignorer le champ role du payload
  • Supprimer le sélecteur de rôle du formulaire d'inscription public.
  • La création d'un admin ne doit être possible que via POST /api/users par un admin authentifié.
C2 — Broken Access Control

DebugAuthController — Promotion admin sans vérification de rôle

OWASP A01:2021 – Broken Access Control
🔴 Critique

DebugAuthController::fixAdminRole() promeut instantanément n'importe quel utilisateur authentifié en admin, sans aucune Gate, aucune vérification de rôle préalable. La route est documentée dans le fichier et peut être activée accidentellement.

📄 fleet-mgt-api/app/Http/Controllers/DebugAuthController.php:63 
public function fixAdminRole(Request $request)
{
    $user = $request->user(); // tout utilisateur authentifié
    $user->role = 'admin';    // aucune gate, aucun contrôle
    $user->save();
}

Impact : Un driver ou un comptable peut s'auto-promouvoir admin en appelant GET /api/fix-admin-role. Compromission totale du contrôle d'accès.

✓ Correction
  • Supprimer définitivement DebugAuthController.php de la codebase.
  • Les outils de debug doivent être des commandes Artisan (php artisan make:admin), jamais des routes HTTP.
  • Vérifier que ces routes ne sont pas enregistrées dans routes/api.php.

🟠 Vulnérabilités Élevées

H1 — Security Misconfiguration

APP_DEBUG=true actif en configuration déployée

OWASP A05:2021 – Security Misconfiguration
🟠 Élevé

Le mode debug Laravel est activé. En cas d'erreur, le framework retourne des stack traces complètes incluant les chemins de fichiers, les variables d'environnement et le contenu des requêtes SQL — des informations qui facilitent considérablement une attaque ciblée.

📄 fleet-mgt-api/.env:2-4
APP_ENV=local
APP_DEBUG=true   ← doit être false hors machine de développement
✓ Correction
APP_ENV=production
APP_DEBUG=false
H2 — Security Misconfiguration

CORS wildcard (*) incompatible avec les credentials

OWASP A05:2021 – Security Misconfiguration
🟠 Élevé

Deux configurations CORS coexistent et se contredisent. CorsMiddleware.php écrase la configuration Laravel en posant Access-Control-Allow-Origin: *, ce qui est invalide avec supports_credentials: true. Cette contradiction crée un comportement imprévisible selon les navigateurs.

📄 fleet-mgt-api/app/Http/Middleware/CorsMiddleware.php 📄 fleet-mgt-api/config/cors.php 
// CorsMiddleware.php — PROBLÈME
$response->headers->set('Access-Control-Allow-Origin', '*');

// cors.php — incohérent
'supports_credentials' => true,  // incompatible avec *
✓ Correction
  • Supprimer CorsMiddleware.php entièrement.
  • Utiliser uniquement config/cors.php avec des origines explicites.
  • Ne jamais combiner allowed_origins: ['*'] avec supports_credentials: true.
H3 — Cryptographic Failures

Credentials réels en clair dans le fichier .env

OWASP A02:2021 – Cryptographic Failures
🟠 Élevé

Le fichier .env contient des secrets réels en clair. Si ce fichier est exfiltré (machine compromise, commit accidentel, accès au serveur), tous les comptes associés sont à risque.

📄 fleet-mgt-api/.env
DB_PASSWORD=david1    ← mot de passe faible
MAIL_PASSWORD=xsmtpsib-5a970192...  ← clé SMTP Brevo réelle
APP_KEY=base64:0oUPUZLOr07...      ← clé de chiffrement Laravel
✓ Correction immédiate
  • Révoquer immédiatement la clé SMTP Brevo depuis le dashboard Brevo.
  • Remplacer DB_PASSWORD=david1 par un mot de passe fort (≥ 20 caractères aléatoires).
  • Régénérer APP_KEY : php artisan key:generate.
  • Vérifier l'historique Git : git log --all -- fleet-mgt-api/.env.
H4 — Identification & Authentication Failures

Token d'authentification stocké en localStorage

OWASP A07:2021 – Identification and Authentication Failures
🟠 Élevé

Le token Sanctum Bearer est stocké en localStorage, accessible à n'importe quel script JavaScript. Une seule faille XSS — même dans une dépendance npm tierce — suffit à exfiltrer le token et à usurper l'identité de l'utilisateur.

📄 fleet-mgt-frontend/src/context/AuthContext.jsx:41
localStorage.setItem('token', accessToken);  // vulnérable au vol via XSS
✓ Correction
  • Passer au mode cookie HttpOnly + SameSite=Strict de Sanctum (mode SPA).
  • Les cookies HttpOnly sont inaccessibles au JavaScript — le token ne peut pas être volé par XSS.
  • Configurer SANCTUM_STATEFUL_DOMAINS et utiliser le endpoint CSRF de Sanctum.
H5 — Broken Access Control

Endpoint de recherche public exposant des données métier

OWASP A01:2021 – Broken Access Control
🟠 Élevé

La route GET /api/search est publique (sans authentification). Elle retourne des données sur les véhicules, les consommations, les maintenances et les noms d'utilisateurs à n'importe quel requérant non authentifié. C'est une fuite d'information directe.

📄 fleet-mgt-api/routes/api.php:19
// AVANT — route publique
Route::get('/search', [SearchController::class, 'search']);
✓ Correction
// APRÈS — déplacer dans le groupe protégé
Route::middleware('auth:sanctum')->group(function () {
    Route::get('/search', [SearchController::class, 'search']);
    // ...
});

🟡 Vulnérabilités Moyennes

M1 — Security Misconfiguration

adminer.php présent à la racine du projet

OWASP A05:2021 – Security Misconfiguration
🟡 Moyen

Le fichier adminer.php (235 Ko) est un outil d'administration de base de données complet, accessible via navigateur. Sa présence dans la racine du projet constitue un risque d'exposition si le serveur de développement est accessible sur le réseau local ou Internet.

✓ Correction

Supprimer le fichier : rm adminer.php. L'accès à la base en développement passe uniquement par le conteneur Docker interne.

M2 — Security Misconfiguration

Port MySQL 3306 et Adminer 8080 exposés publiquement en dev

OWASP A05:2021 – Security Misconfiguration
🟡 Moyen

Le fichier docker-compose.yml expose le port MySQL et Adminer sur toutes les interfaces réseau de la machine hôte, les rendant accessibles depuis le réseau local ou, en cas de machine cloud, depuis Internet.

📄 docker-compose.yml
db:
  ports:
    - "3306:3306"   ← accessible depuis l'extérieur
adminer:
  ports:
    - "8080:8080"   ← interface web DB exposée
✓ Correction

Supprimer les mappings de ports pour db et adminer. La communication doit rester interne au réseau Docker (expose au lieu de ports).

M3 — Security Misconfiguration

Absence de headers de sécurité HTTP

OWASP A05:2021 – Security Misconfiguration
🟡 Moyen

Aucun header de sécurité HTTP standard n'est configuré côté API ou frontend :

Content-Security-Policy       ← absent  (protection XSS)
X-Frame-Options: DENY         ← absent  (protection clickjacking)
X-Content-Type-Options: nosniff ← absent
Strict-Transport-Security     ← absent  (forcer HTTPS)
Referrer-Policy               ← absent
✓ Correction

Ajouter un middleware Laravel SecurityHeadersMiddleware ou configurer ces headers au niveau du reverse proxy (Nginx / Cloudflare). Cloudflare Pages gère automatiquement HSTS et certains headers.

M4 — Cryptographic Failures

SESSION_ENCRYPT=false et cookie de session non sécurisé

OWASP A02:2021 – Cryptographic Failures
🟡 Moyen

Le chiffrement des sessions en base de données est désactivé. Le cookie de session n'est pas forcé en HTTPS (SESSION_SECURE_COOKIE non défini), ce qui peut permettre une interception en clair sur des réseaux non chiffrés.

📄 fleet-mgt-api/.env:28
SESSION_ENCRYPT=false   ← données de session non chiffrées en base
✓ Correction
SESSION_ENCRYPT=true
SESSION_SECURE_COOKIE=true

🔵 Vulnérabilités Faibles

L1 — Security Logging & Monitoring Failures

console.log avec données utilisateur sensibles

OWASP A09:2021 – Security Logging and Monitoring Failures
🔵 Faible

Des console.log exposent l'objet utilisateur complet et l'état de session dans les DevTools du navigateur. Ces logs sont visibles par toute personne ayant accès à la machine ou à des outils de monitoring tiers.

📄 fleet-mgt-frontend/src/context/AuthContext.jsx:37,43
console.log('🔐 Tentative de connexion...', userData); // expose l'objet user
console.log('✅ Connexion réussie, redirection vers /dashboard');
✓ Correction

Supprimer tous les console.log avant déploiement. Utiliser une variable import.meta.env.DEV pour les garder uniquement en développement.

L2 — Cryptographic Failures

Connexion base de données sans SSL (DB_SSL_MODE=DISABLED)

OWASP A02:2021 – Cryptographic Failures
🔵 Faible

Le trafic entre l'API Laravel et MySQL n'est pas chiffré. En production avec une base distante (Railway, PlanetScale, RDS…), les données traversent le réseau en clair.

📄 fleet-mgt-api/.env:27
DB_SSL_MODE=DISABLED
✓ Correction

Activer DB_SSL_MODE=REQUIRED et fournir le certificat CA du provider de base de données.

L3 — Identification & Authentication Failures

Mot de passe base de données trop faible

OWASP A07:2021 – Identification and Authentication Failures
🔵 Faible

Le mot de passe de la base de données (david1) ne respecte pas les bonnes pratiques : trop court, pas de complexité suffisante, potentiellement dans des dictionnaires de brute force courants.

✓ Correction

Utiliser un mot de passe généré aléatoirement d'au moins 24 caractères en production. Exemple : openssl rand -base64 32.

Plan d'action — Corrections prioritaires

  • 1

    Verrouiller l'inscription publique — retirer 'admin' des rôles acceptables [C1]

    AuthController.php:28 — modifier la validation pour n'accepter que driver/manager/accountant. Supprimer le sélecteur de rôle du formulaire public.

  • 2

    Supprimer DebugAuthController.php [C2]

    Ce fichier ne doit pas exister en production. Le remplacer par une commande Artisan si nécessaire en dev.

  • 3

    Révoquer la clé SMTP Brevo immédiatement [H3]

    Se connecter au dashboard Brevo et régénérer la clé API. Changer aussi DB_PASSWORD et régénérer APP_KEY.

  • 4

    Passer APP_DEBUG=false pour tout déploiement non local [H1]

    Créer un fichier .env.prod séparé avec APP_ENV=production et APP_DEBUG=false.

  • 5

    Authentifier /api/search et corriger CORS [H5, H2]

    Déplacer la route search dans le groupe auth:sanctum. Supprimer CorsMiddleware.php et utiliser uniquement config/cors.php.

  • 6

    Migrer le token vers des cookies HttpOnly [H4]

    Activer le mode SPA de Sanctum avec cookies HttpOnly + SameSite=Strict. Supprimer le stockage en localStorage.

  • 7

    Ajouter les headers de sécurité HTTP [M3]

    Créer SecurityHeadersMiddleware ou configurer au niveau Nginx/Cloudflare : CSP, X-Frame-Options, HSTS, nosniff.

  • 8

    Activer SESSION_ENCRYPT=true et supprimer adminer.php [M1, M4]

    Mettre SESSION_ENCRYPT=true et SESSION_SECURE_COOKIE=true. Supprimer adminer.php du répertoire racine.
